# Step 1: Frame the decision

Write down exactly what's being decided before looking at options. Most appraisals that go wrong do so here, because people are quietly answering different questions.

| | |
|---|---|
| Skip if | The decision-maker has already agreed a written frame |
| You'll end up with | A one-page frame (workbook Frame tab) and a principles table |
| Next | Step 2 |

Before this step, Tree 1 in SKILL.md identifies the type of choice; load its file from `choices/`.

## 1.1 The frame

- **Decision**: what is being chosen, for what purpose, over what period, in one sentence.
- **Decision-maker and date**.
- **Need, stated without naming a solution** ("move chilled food from donors to hubs", not "a logistics contract"). Stating the need solution-neutrally keeps genuine alternatives open (the first GAO practice for analysing alternatives).
- **In scope / out of scope**, including adjacent decisions handled elsewhere.
- **What happens next** (more analysis, procurement, launch). This sets how much detail is needed now.
- **Decision hierarchy**: sort related decisions into *already decided* (treat as constraints), *deciding now*, and *deciding later*. Deferring a decision until information arrives is itself a way to keep options open (Step 9.1); say what will trigger the later decision.

If the choice sits in a chain (scope → what → where → structure → who → design choices), note which earlier links are settled and which are assumed.

## 1.2 Principles

A bare principle ("be proportionate") can't be tested, so write each as three parts:

| About the process or the result? | Principle | Issue it addresses | What it implies |
|---|---|---|---|
| Result | Must work within existing budgets in year one | No new funding until the spending review | Options needing new legal entities are phased, not excluded |
| Process | Must be proportionate to the decision | Risk of over-engineering a small choice | 4–8 statements per success factor; no costed analysis at long-list stage |

Process principles ("the appraisal must…"): transparent, proportionate, uses existing evidence and expertise, built with the people who'll live with the result. Result principles ("the chosen option must…") often become criteria or knock-outs in Step 5; say which.

## 1.3 Which layer are you deciding?

Many confused appraisals mix three questions. Name the one this appraisal answers:

| Layer | Question | Usual type of choice |
|---|---|---|
| Activity model | *What* is done, and when? | What (`choices/what.md`) |
| Operating model | *Who* provides it: the nature of the vehicle | Structure (`choices/structure.md`) |
| Transaction model | *How* agreements are set up and managed | Structure by situation (`choices/structure-by-situation.md`) |

Form follows function: settle activities before choosing a vehicle where you can, and the vehicle before standardising transactions. If a layer is fixed elsewhere, record it as an assumption.

## Checklist
- [quick] Decision written in one sentence: what is chosen, by whom, by when, and what happens next
- [quick] Need stated without naming a solution
- [standard] Related decisions sorted: already decided / deciding now / deciding later
- [standard] Principles written as principle, issue it addresses, what it implies
- [standard][structure] Layer named: activity, operating or transaction model
- [quick] Frame agreed with the decision-maker
