# Step 5: Agree criteria, scores and weights

Decide how options will be judged before anyone looks at the evidence. Rules agreed after seeing results tend, even unconsciously, to favour a preferred option.

| | |
|---|---|
| Skip if | Criteria, score definitions, weights and combining rules are already agreed; or the method doesn't score (a quantified tree in money, a matching decision tree, pros and cons). For those, agree only the knock-outs (§5.1) |
| You'll end up with | An agreed criteria table: knock-outs, criteria with score definitions, weights, combining rules (workbook Criteria and Indicators tabs) |
| Next | Step 6 |

## 5.1 Knock-outs and deal-breakers

- **Knock-out**: a condition that excludes a whole option before scoring, whatever else is true (disqualifying safety record, sanctions, legal impossibility, exclusive arrangement elsewhere, outside scope). Excluded options are listed with the reason, never scored and ranked: a disqualified option sitting at 3/9 in a table invites confusion. This separation of "musts" from "wants" comes from Kepner-Tregoe decision analysis.
- **Deal-breaker**: within a success factor, one statement whose failure fails the whole factor (e.g. "has the legal powers to act"). Tag before scoring.
- **Ethics and reputation**: decide now whether serious issues are knock-outs, deal-breakers or context. Left "for information", they sit beside a high score without affecting it.

## 5.2 Criteria and score definitions

For each criterion write:
- **Name and the question it asks** ("Quality: how confident are we they can reliably produce to the required standard?").
- **What earns each score**, ideally countable ("serves all 6 regions = 3"; "independent mentions in feedback: 1 → 1, 2–3 → 2, 4+ → 3"). Without written definitions, two scorers' "2" means different things.
- **Sub-statements** where a criterion needs breaking down (4–8 is plenty), each worded so that "yes" is good: "does not require new legislation", not "requires new legislation".
- **The evidence that would show it**, and where it will come from.
- **Setup vs ongoing**, where timing matters.

Check the set:
- Will each criterion separate the options? If everything will score the same, drop or redefine it.
- Do two criteria measure the same thing? Each issue belongs to one criterion only.
- **Independence**: if someone says "it depends" ("speed matters only if cost is low"), the criteria are interlinked and adding scores will mislead; merge or restate them.
- **Cost**: keep it out of the benefit criteria and compare value against cost separately (scoring it in double-counts and hides the trade-off). Quick location grids may keep cost as a criterion; say so.
- Local criteria (e.g. regulatory landscape, external confidence) must be justified by something real in this context.

## 5.3 Weights

**Recommend swing weighting; let the group overrule it.**

1. For each criterion, picture the swing from the worst to the best option actually on the table, not the theoretical extremes. Before scoring, judge the swing from what's known about the long list ("the options range from no presence in the target markets to an office in each"). If scoring later shows the real range is very different, revisit the weights openly and record it in the decisions log.
2. Ask which swing the group would most like to make; give it 100 points.
3. Rate each other swing against it (e.g. 80, 50, 40).
4. Divide each by the total so the weights add to 100% (100 + 80 + 50 + 40 = 270; 100 ÷ 270 = 37%).

Why: weights should reflect how much the real difference between these options matters, not how important a criterion sounds. "Quality" may be vital, but if every option is similar on quality it shouldn't drive the ranking. It's the method recommended in UK government guidance on multi-criteria analysis. Alternatives: **equal weights** (simplest; fine for a quick screen with few criteria) or **importance weights** (intuitive, but can let a criterion that barely separates the options dominate; not acceptable for Green Book weighted analysis).

## 5.4 Combining rules

Write down how scores or ratings combine, before scoring. The method file gives the defaults (e.g. `methods/rag-success-factors.md` for red/amber/green). If the group later finds it valued something (say, speed) more than the agreed weights reflect, it should say so and re-run, not quietly adjust scores.
