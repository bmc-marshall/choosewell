# Type of choice: Design choices (team, funding, name, hosting, and similar)

Use for the smaller decisions that follow a main choice (or stand alone): how to set up the team, how to fund the service, what to call it, which body hosts it, where it sits. Each has two to four options and needs a clear, honest recommendation rather than a full appraisal.

## Default method

**Pros and cons with option labels** (`methods/pros-and-cons.md`): deciding criterion stated first; principles as knock-outs; one-line description per option; parallel ✓/✗ lists; labels Preferred / Do minimum / Do nothing / Alternative; recommendation with what would confirm it. Escalate to scored criteria or RAG only if the decision is contested or high-stakes.

## Common choices and option starters

**Team set-up** (within a host organisation, assuming a given size):
- *Ringfenced team*: dedicated staff, ringfenced funding transfer. Typically ✓ resilient to change, clear accountability, easy funding flows, ROI tracking, ownership, easier recruitment; ✗ siloes/duplication, less adaptable, transition to manage, possible impact on the host's mandate.
- *Distributed / partially ringfenced*: portions of existing roles, partly cross-charged. ✓ some resilience and ROI tracking, synergies with existing teams, balances accountability and integration, flexible for staff; ✗ management burden, budget tracking overhead, competing priorities, role confusion. (Often "do minimum".)
- *Fully integrated*: no formal separation. ✓ synergies, clear relationship management, minimal change; ✗ exposed to policy change, unclear accountability, little ROI tracking, competing priorities, recruiting specialist skills. (Often "do nothing".)
Show each as a small org diagram under the same head.

**Funding model** (for a service with a central budget):
- *Central funding only*: ✓ foundation investment, budget certainty, signals support, maximises engagement; ✗ no performance incentive, may reduce net income.
- *Central + buyer management fee*: ✓ performance incentive, more net income, matches competitors' mixed models, reflects service; ✗ higher cost may deter some buyers.
- *Central + supplier management fee*: ✓ reflects service, some incentive; ✗ damages relationships, fewer engaged organisations, may be seen as double funding.
- *Membership*: ✓ revenue independent of wins; ✗ fewer engaged organisations, excludes parts of the ecosystem, confusion with existing associations.
Note where further modelling would quantify income under each.

**Name** *(supporting, not core: Choosewell can structure a naming shortlist once the structure is settled, but it isn't built for naming. Before starting, tell the user it won't do linguistic and cultural checks in each market, trademark and domain searches or audience testing, all of which a real naming exercise needs, and label the output as a starting point)*: first ask the sector, target markets and audiences, and any brand rules (these can decide the answer); then principles from the parent brand (written in full, required identifiers, partnership/organisation/service conventions) → lexicon of existing names in the landscape (a light web search for organisations already using each name in the same field is expected; say clearly it is not a trademark search) → how comparable bodies chose → shortlist with pros/cons (resonance in target markets, internal appeal, confusion risks, past associations) → user testing → recommendation. State the deciding criterion (e.g. works overseas and keeps public confidence, rather than describing the function). The benchmark ("do minimum") is a plain descriptive name.

**Hosting**: options (bodies that could host) × models (e.g. hosted programme vs company), with pros/cons per pairing and a recommendation row; separate who is involved in decisions and announcements from who runs operations.

## Outputs

Option cards with labels; org-structure mini-diagrams; pros/cons tables; host × model grid; a one-line recommendation per choice feeding an "answer on a page" (scope, activity, phasing, operating model, team, funding).
